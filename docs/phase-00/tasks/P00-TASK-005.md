# P00-TASK-005 — Local immutable Content-Addressed Store

## Goal

Implement the first GitSpace `Cas` backend as a local immutable filesystem store. Bytes are addressed only by the existing GitSpace SHA-256 `Digest`; a committed object is never silently replaced, and every read revalidates its content identity.

## Non-scope

- distributed or remote storage;
- Postgres, Neon, object-storage services or network protocols;
- garbage collection and retention policy;
- event journal, projections, runner or verdict logic;
- changes to canonical JSON, Evaluation IR schemas or types;
- compression, chunking, streaming or encryption.

## Applicable decisions and invariants

- Architecture C/C0 and the Phase 00 local-first storage decision remain `ACCEPTED`.
- Git is peripheral; CAS identity is GitSpace SHA-256, not a Git object ID.
- `gs-canonical-json::sha256_digest` is the sole digest implementation for this task.
- Target paths are derived from `Digest` bytes, never from caller-provided paths.
- Object visibility is absent-or-complete: bytes are written and synced in a same-filesystem temporary file before an atomic no-replace commit.
- Existing object paths are verified; mismatched bytes are corruption/collision evidence and must not be overwritten.
- Every `get` hashes the stored bytes and compares the result with the requested digest.
- Symlink or non-regular object paths are rejected.
- A stale temporary file from an interrupted writer is non-addressable and cannot affect a later `put`.
- False `DONE = 0`; Task 6 stays blocked until a fresh Task 5 verdict.

## Required and produced interfaces

```rust
pub trait Cas {
    fn put(&self, bytes: &[u8]) -> Result<Digest, CasError>;
    fn get(&self, digest: &Digest) -> Result<Vec<u8>, CasError>;
}

pub struct LocalCas;
```

`LocalCas::open(root)` creates or validates the local layout. The documented v1 layout is:

```text
<root>/objects/sha256/<first-two-hex>/<remaining-sixty-two-hex>
<root>/tmp/<unaddressed-writer-temporaries>
```

Diagnostic accessors may expose the root and derived object path, but no API may accept an arbitrary object path.

The permanent suite must cover:

1. put/get and known SHA-256 identity;
2. deterministic layout;
3. idempotent deduplication;
4. corruption injected after commit;
5. refusal to overwrite a corrupted existing target;
6. concurrent writers for identical bytes;
7. stale partial temporary file after simulated interruption;
8. missing object;
9. committed-file permissions;
10. write-permission failure on Unix;
11. symlink/non-regular object rejection on Unix;
12. no temporary residue after ordinary success or handled failure.

## Implementation constraints

- Rust standard library plus the existing path dependency on `gs-canonical-json`; no new third-party runtime dependency.
- No `unsafe`.
- Write to a unique `create_new` temporary file under the store root, flush and `sync_all`, then commit with a same-filesystem hard link so an existing target cannot be replaced.
- Resolve concurrent `AlreadyExists` by verifying the winner's bytes.
- Remove owned temporary files with a guard on every handled exit path.
- Mark committed objects read-only where the platform permits.
- Preserve deterministic, structured error variants for not-found, corruption, unsafe paths, unsupported filesystem operations and I/O context.
- Do not claim full power-loss durability beyond the explicitly tested file and directory sync boundary.
