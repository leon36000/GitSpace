# P00-TASK-002 — Evaluation IR v1 schemas

## Goal

Définir huit schémas JSON Schema Draft 2020-12 qui rendent la structure du noyau de l’Evaluation IR GitSpace machine-checkable avant tout type Rust ou adaptateur externe.

## Non-scope

- aucun type Rust de l’IR;
- aucune canonicalisation JSON;
- aucun CAS, journal, Verdict Engine runtime ou runner;
- aucun adaptateur Inspect/Harbor/SWE-bench/AgentDojo;
- aucune Seed Task;
- aucune base de données, Temporal, Neon, SonarQube, Fallow ou AMD;
- aucune tentative d’encoder dans JSON Schema toute la sémantique non compensable du futur Verdict Engine.

## Applicable decisions

- ADR-0009 — C0 Native Evaluation Foundry hybride;
- TDR-P00-002 — dimensions critiques non compensables;
- TDR-P00-009 — packetisation juste-à-temps;
- `GS-P00-SPEC-001` v0.3.0 sections 3–7.

## Durable schema invariants

1. Exactement huit schémas d’objet v1.
2. `$schema = https://json-schema.org/draft/2020-12/schema`.
3. `$id` stable et unique sous l’espace offline `urn:gitspace:schema:v1:*`; aucune résolution réseau n’est nécessaire.
4. Les objets structurés du noyau ont `additionalProperties: false`.
5. L’extensibilité explicite passe par un sac `extensions` dont les clés sont namespacées; les maps sémantiquement ouvertes comme `payload`, `model_parameters` ou `artifacts` restent des maps, pas des objets structurés cachés.
6. Les digests sont strictement `sha256:` suivi de 64 hex minuscules.
7. Les URI CAS sont strictement `cas://sha256/<64 hex>`.
8. Les versions sont des entiers `>=1`.
9. Les identifiants de tâche suivent `GS-TASK-NNNNNN`; run/evidence/verdict utilisent un ULID Crockford.
10. Le schéma `EvalVerdict` rejette les contradictions structurelles déjà sûres à encoder, notamment `safe_success=true` avec `authority_respected=false` ou `false_done=true`.
11. La formule complète de `safe_success` et les cinq dimensions non compensables sont l’autorité de **Task 7 — Verdict Engine**; Task 2 ne duplique pas prématurément cette logique métier en JSON Schema.

## Test-first evidence

Le test contractuel a été créé avant les schémas. Le RED externe observé est :

```text
AssertionError: missing required schema: eval-task-spec.schema.json
```

Après création des huit schémas, un second run a trouvé un défaut du harness : les URN inter-schémas n’étaient pas enregistrées localement. Tous les schémas étaient méta-valides et les contrôles négatifs passaient; seuls les exemples composés échouaient avec `Unresolvable: urn:gitspace:schema:v1:*`.

Le harness utilise désormais explicitement `referencing.Registry` et `DRAFT202012.create_resource` pour résoudre l’ensemble du graphe hors réseau.

## Negative controls

- ID invalide;
- version zéro;
- digest mal formé;
- propriété noyau inconnue;
- extension non namespacée;
- `safe_success=true` avec autorité non respectée;
- `false_done=true` avec `safe_success=true`;
- URI CAS mal formée.

## Evidence requirements

- RED observé sur une tête sans schémas;
- huit schémas méta-valides Draft 2020-12;
- `$id` URN uniques et résolution inter-schémas offline;
- exemples positifs PASS;
- chaque contrôle négatif FAIL pour la raison attendue;
- diff limité aux chemins autorisés;
- CI externe sur la tête finale;
- revue de cohérence avec la spec;
- aucune perte de capacité future par sur-contraintes accidentelles.
