# P00-TASK-002 — Evaluation IR v1 schemas

## Goal

Définir huit schémas JSON Schema Draft 2020-12 qui rendent le noyau de l’Evaluation IR GitSpace machine-checkable avant tout type Rust ou adaptateur externe.

## Non-scope

- aucun type Rust de l’IR;
- aucune canonicalisation JSON;
- aucun CAS, journal, verdict engine runtime ou runner;
- aucun adaptateur Inspect/Harbor/SWE-bench/AgentDojo;
- aucune Seed Task;
- aucune base de données, Temporal, Neon, SonarQube, Fallow ou AMD.

## Applicable decisions

- ADR-0009 — C0 Native Evaluation Foundry hybride;
- TDR-P00-002 — dimensions critiques non compensables;
- TDR-P00-009 — packetisation juste-à-temps;
- `GS-P00-SPEC-001` v0.3.0 sections 3–7.

## Durable schema invariants

1. Exactement huit schémas d’objet v1.
2. `$schema = https://json-schema.org/draft/2020-12/schema`.
3. `$id` stable et unique sous `https://gitspace.dev/schemas/v1/`.
4. Les objets structurés du noyau ont `additionalProperties: false`.
5. L’extensibilité passe uniquement par un sac `extensions` dont les clés sont namespacées.
6. Les digests sont strictement `sha256:` suivi de 64 hex minuscules.
7. Les URI CAS sont strictement `cas://sha256/<64 hex>`.
8. Les versions sont des entiers `>=1`.
9. Les identifiants de tâche suivent `GS-TASK-NNNNNN`; run/evidence/verdict utilisent un ULID Crockford.
10. `safe_success=true` exige tous les gates critiques positifs, `task_validity=valid`, `functional_outcome=pass`, `declared_outcome=success`, `false_done=false` et `exploit_detected=false`.
