# P00-TASK-006 — Journal append-only et projections reconstruisibles

## Goal

Ajouter le premier journal d’événements local de GitSpace afin que l’historique autoritaire d’un run soit append-only, que chaque événement soit stocké sous forme canonique dans le CAS, que les offsets soient strictement monotones et qu’une projection de run puisse être reconstruite bit-à-bit après suppression.

## Non-scope

- journal distribué, réplication ou consensus;
- Temporal, Restate, Neon ou PostgreSQL;
- compaction, rétention ou garbage collection;
- réparation automatique d’une queue tronquée;
- snapshots persistants;
- verdict engine, runner, CLI, adaptateurs ou Seed Suite;
- modification des schémas Evaluation IR v1;
- chiffrement ou défense contre un attaquant possédant déjà l’écriture arbitraire sur le filesystem.

## Journal format v1

Le journal d’un run est un fichier local dérivé du SHA-256 du `run_id`, jamais du texte non fiable utilisé directement comme chemin.

```text
header (40 bytes)
  magic              8 bytes = GSEJ0001
  run_id_digest     32 bytes

record (72 bytes, repeated)
  offset             8 bytes, unsigned big-endian
  event_digest      32 bytes, canonical RunEvent stored in CAS
  chain_digest      32 bytes
```

```text
chain[0] = SHA256("GSEJ-CHAIN-V1" || run_id_digest || offset || event_digest)
chain[n] = SHA256("GSEJ-CHAIN-V1" || chain[n-1] || offset || event_digest)
```

## Core invariants

1. `EventOffset == RunEvent.sequence`, zero-based and contiguous.
2. `RunEvent.run_id` equals the journal run ID.
3. `payload_digest` equals the canonical SHA-256 of `payload`.
4. The complete RunEvent passes the offline Draft 2020-12 schema before append.
5. Canonical event bytes are written to CAS before their journal pointer.
6. A crash between CAS write and journal append may create an orphan CAS object but no visible event.
7. Cooperative writers acquire `std::fs::File::lock()` before inspecting or appending.
8. An identical retry at an existing offset is idempotent.
9. A different event at an existing offset is a conflict.
10. A sequence gap, corrupt header, invalid chain or truncated tail fails closed.
11. No append truncates, repairs, heals or overwrites existing journal bytes.
12. Every committed append calls `sync_all()` before success is returned.
13. A projection is derived only by replaying verified events from journal + CAS.

## Documented platform boundary

Rust 1.97.1 documents that append mode positions writes at EOF but does not alone prevent interleaving or partial writes. GitSpace therefore holds the cooperative exclusive file lock for the full inspect/write/sync sequence. `File::lock()` remains advisory on some platforms: arbitrary non-cooperating filesystem writers are outside this task’s guarantee.

`sync_all()` attempts to flush content and metadata, but Task 6 does not claim arbitrary-filesystem power-loss durability or parent-directory persistence across every platform.

## Required tests

### Contract

- append/read round trip;
- monotonic offsets and ordered replay;
- identical retry is idempotent;
- sequence gap rejected;
- payload digest mismatch rejected;
- projection bytes identical after deletion and rebuild;
- CAS object written without pointer remains invisible.

### Adversarial

- truncated header rejected;
- truncated record tail blocks read and append;
- changed chain digest rejected;
- same sequence with different event rejected;
- journal file replaced by a symlink rejected where supported;
- concurrent identical writers converge to one committed record;
- run ID mismatch rejected;
- corrupt or missing CAS event rejected.
