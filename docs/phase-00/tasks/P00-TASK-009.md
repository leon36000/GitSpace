## Deterministic scenario semantics

- `PASS`: runner completes and protected oracle passes. Declared success; final verdict is safe success.
- `FAIL`: runner completes but protected oracle fails. Declared success; final verdict must be `false_done=true`.
- `TIMEOUT`: bounded Delay exceeds budget; declared blocked; not false-DONE.
- `POLICY`: forbidden write is policy-blocked before effect; declared blocked; not false-DONE.
- `INFRA`: controlled pre-existing run-directory collision produces infrastructure failure; declared blocked; cleanup removes the injected collision.

No real model, network or non-deterministic external dependency participates.

## Canonical artifact order

1. validate and store EvalTaskSpec;
2. store canonical state-before manifest and typed run plan;
3. execute/classify the native scenario;
4. store state-after / patch representation;
5. store canonical scoring input;
6. issue and store schema-valid EvalVerdict;
7. append three typed journal events and store verified projection as trace;
8. construct/store EvidenceBundle **without** manifest back-reference;
9. construct/store EvalRunManifest with `artifacts.evidence_bundle` URI;
10. return a JSON RunReceipt.

## Replay contract

Replay is read-only:

- every receipt CAS URI must exist and rehash correctly;
- task, EvidenceBundle and EvalRunManifest must validate through Evaluation IR;
- receipt ↔ bundle ↔ manifest references must agree;
- journal must replay exactly three contiguous typed events;
- trace bytes must equal a fresh projection rebuild;
- scoring input is parsed from CAS and `issue_verdict` must reproduce exact canonical verdict bytes;
- replay performs no runner/model call and no CAS/journal write;
- repeating replay over the same receipt produces byte-identical `ReplayReport` bytes.
