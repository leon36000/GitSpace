## Opening authority

```text
open
  → may create the Foundry, CAS, journal and runner layout
  → produces an execution-enabled handle

open_read_only
  → requires an existing real Foundry root
  → requires existing CAS objects/sha256, CAS tmp, journal and journal/runs
  → never opens or recreates runner
  → produces a handle whose run method fails before effects
```

The CLI `run` path must use `open`. The CLI `replay` path must use `open_read_only`.

## Deterministic scenario semantics

### PASS

Runner completes and protected oracle passes. Classification is `pass`, but the persisted verdict **must not self-promote to safe success**. At verdict issuance time the EvidenceBundle, replay and identity-independent verification do not yet exist.

Therefore the historical verdict is:

```text
functional_outcome = pass
declared_outcome = blocked
safe_success = false
false_done = false
evidence coverage = 0/1
replay_passed = false
independent_verification_passed = false
```

Replay later verifies evidence and deterministic rescoring separately through `ReplayReport.replay_verified` and `evidence_verified`; it does not rewrite the historical verdict. A later independently verified success may issue a superseding verdict in a future verification step.

### FAIL

Runner completes but protected oracle fails. The fixture deliberately declares `success` so the verdict must produce `false_done=true`.

### TIMEOUT

Bounded Delay exceeds budget; declared blocked; not false-DONE.

### POLICY

Forbidden write is policy-blocked before effect; declared blocked; not false-DONE.

### INFRA

Controlled pre-existing run-directory collision produces infrastructure failure; declared blocked; cleanup removes the injected collision.

No real model, network or non-deterministic external dependency participates.

## Canonical artifact order

1. validate and store EvalTaskSpec;
2. store canonical state-before manifest and typed run plan;
3. execute/classify the native scenario;
4. store state-after / patch representation;
5. store canonical scoring input representing proof state **at verdict issuance time**;
6. issue and store schema-valid historical EvalVerdict;
7. append three typed journal events and store verified projection as trace;
8. construct/store EvidenceBundle **without** manifest back-reference;
9. construct/store EvalRunManifest with `artifacts.evidence_bundle` URI;
10. return a JSON RunReceipt.

`source_commit` and EvidenceBundle `commit_sha` are bound to the exact Git commit actually executed when Git metadata is available. Clean archive tests may use an explicit all-zero synthetic digest only as a contract fixture and must never report it as repository provenance.

## Deterministic identity contract

Run, verdict and evidence identifiers share one schema-compatible 26-character Crockford Base32 suffix. It is derived as the first 128 bits of:

```text
SHA-256(
  "gitspace:p00-task-009:identity:v1"
  || NUL
  || source_commit
  || NUL
  || scenario_slug
)
```

Therefore:

- identical `(source_commit, scenario)` inputs reproduce the same IDs and preserve idempotence;
- a different source commit or scenario produces a different qualified identity;
- two commits may coexist in one Foundry store without sharing a run ID;
- cross-commit replay fails because both the identity and full source commit are checked;
- the Crockford suffix is ULID-shaped for schema compatibility but carries no timestamp semantics;
- the full source commit remains authoritative provenance evidence; the 128-bit suffix is only the deterministic routing identity.

## Replay contract

Replay is read-only and fail-closed:

- the CLI opens replay through `open_read_only`, never through the initializing constructor;
- an absent Foundry root fails without creation;
- a missing required CAS or journal directory fails without repair;
- the runner root is neither required, opened nor recreated;
- a read-only handle cannot execute a scenario;
- the CAS/journal layout is revalidated immediately before CAS opening;
- receipt source commit must match the opened Foundry;
- receipt run ID must match the qualified `(source_commit, scenario)` identity;
- every receipt CAS URI must exist and rehash correctly;
- task, EvidenceBundle, EvalRunManifest and stored verdict must validate through Evaluation IR;
- receipt ↔ bundle ↔ manifest references must agree;
- EvidenceBundle and RunManifest must match the qualified deterministic Task 9 environment;
- task, plan, state-before, state-after, patch and scoring bytes must match the qualified deterministic artifacts exactly;
- journal must replay exactly three contiguous complete typed events;
- trace bytes must equal a fresh projection rebuild;
- scoring input is parsed from CAS and `issue_verdict` must reproduce exact historical verdict bytes and identity;
- replay performs no runner/model call and no CAS, journal or layout write;
- a successful replay reports `replay_verified=true` and `evidence_verified=true` without mutating the historical verdict;
- repeating replay over the same receipt produces byte-identical `ReplayReport` bytes.
