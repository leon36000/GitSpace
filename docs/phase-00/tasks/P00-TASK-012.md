## 9. Oracle and classification semantics

Harbor 0.21.0 `OracleAgent` peut produire `agent/exit-code.txt` sur exit non-zéro sans lever automatiquement une exception.

Le collecteur publie toujours un artefact canonique `oracle_exit_status` :

```json
{"present":false,"value":null}
```

ou :

```json
{"present":true,"value":0}
```

Le raw `oracle_exit_code` est conditionnel. Non-zéro/malformé/contradictoire => `INFRA` + `task_invalid_candidate=true` pour `qualification_oracle`.

Précédence :

```text
POLICY → INFRA → TIMEOUT → terminal
```

- `POLICY` : uniquement preuve GitSpace attribuable de violation capability/path/montage/egress/secret/oracle/daemon; jamais par parsing d'un message externe.
- `INFRA` : process Harbor non-zéro; worker/base/sidecar non qualifié; image/digest divergents; start/setup/verifier failure; reward absente/malformée; exception/stage inconnus; cardinalité incorrecte; CAS/filesystem/cleanup invalide; oracle exit non-zéro; oracle reward `0`; ambiguïté.
- `TIMEOUT` : uniquement exact `AgentTimeoutError` au stage `agent_execution`, après setup/env valides et aucune gate supérieure; reward `None`.
- `PASS` : toutes gates vertes + process `0` + reward exact int `1` + CAS/cleanup verts.
- `FAIL` : uniquement `run_purpose=status_control`, gates vertes + reward exact int `0`.

Pour `qualification_oracle`, le seul terminal fonctionnel admissible est PASS. Une reward `0` de l'oracle de référence indique `INFRA`/candidat `TASK_INVALID`, jamais échec d'un agent évalué.
