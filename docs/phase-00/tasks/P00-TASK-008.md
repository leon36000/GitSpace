# P00-TASK-008 — Runner local tool-mediated et isolation d’oracle

## Goal

Exécuter une fixture locale déterministe dans un workspace agent distinct d’un oracle protégé, avec capabilities minimales, effets attribuables, timeout coopératif, snapshot CAS et cleanup systématique.

## Security boundary

Task 8 est volontairement **tool-mediated** : l’agent évalué ne reçoit que des opérations typées (`read`, `write`, `delay`) interprétées par GitSpace. Cette tâche ne prétend pas isoler du code natif arbitraire, un shell, du WASM non fiable ou un processus hostile. La vraie isolation processus/VM appartient à la phase Capability Security + Sandboxes.

## Non-scope

- exécution de shell, binaire, script ou WASM non fiable;
- gVisor, Firecracker, Kata, container runtime ou seccomp;
- réseau, secrets, egress ou broker;
- verdict engine, journal, CLI, adaptateur ou modèle;
- policy language général;
- base de données, Temporal, Neon ou stockage distribué;
- protection contre un processus natif concurrent possédant l’écriture arbitraire sur le même filesystem;
- modification des schémas Evaluation IR;
- state/RAGLite avant preuve post-merge.

## Path and capability invariants

1. Agent operation paths must be non-empty UTF-8 relative paths containing only `Component::Normal` components.
2. Absolute paths, prefixes, `.` and `..` are rejected before filesystem access.
3. Capability prefixes are component-aware; `src` does not authorize `src2`.
4. Empty capability prefix means the complete workspace and is explicit.
5. Fixture and oracle paths use the same strict relative-path parser.
6. Existing symlinks are rejected on every traversed component before read/write/snapshot.
7. Agent operations can resolve only below `workspace/`; no API accepts `oracle/` as an agent root.
8. Workspace and oracle directories are siblings inside a fresh run directory derived from SHA-256(run_id), never from raw untrusted text.

Rust 1.97.1 `Path::components()` is used to distinguish `Prefix`, `RootDir`, `CurDir`, `ParentDir` and `Normal`. `symlink_metadata` is used because it reports the link itself rather than following it. These checks protect the tool-mediated fixture boundary; they are not claimed as a hostile native-process sandbox.

## Timeout semantics

`std::time::Instant` supplies a monotonic deadline. The runner checks the deadline before every operation and again after `Delay`. `Delay` is the deterministic test hook for a cooperative long-running tool call. Task 8 guarantees that no later effect executes after the deadline; it does not preempt arbitrary native code inside an operation because such code is out of scope.

## Execution order

```text
validate plan
→ create fresh run/workspace/oracle directories
→ materialize fixture + oracle
→ start monotonic deadline
→ interpret agent operations sequentially
→ on each allowed read/write: commit bytes to CAS + append Effect
→ policy/timeout stops subsequent operations
→ if operations complete: evaluate protected oracle checks
→ snapshot current workspace recursively, reject symlinks, sort paths
→ commit snapshot manifest to CAS
→ cleanup run directory
→ return RunResult
```

## Snapshot contract

Each regular workspace file is re-read after execution, committed to CAS and represented as:

```json
{"path":"relative/file","digest":"sha256:..."}
```

Entries are sorted lexicographically by path. The canonical JSON array is committed to CAS; its digest is `workspace_snapshot`. The run directory is then deleted. The result remains replayable from CAS references without retaining the mutable workspace.

## Required tests

### Contract

- allowed read returns CAS digest and ordered effect;
- allowed write persists in final snapshot;
- snapshot manifest is deterministic and canonical;
- `src` capability does not authorize sibling `src2`;
- empty prefix explicitly authorizes whole workspace;
- `../oracle/secret` read is policy blocked before I/O;
- `../oracle/secret` write is policy blocked before I/O;
- policy block stops all later effects;
- delay crossing deadline yields `TimedOut` and stops all later effects;
- successful oracle check yields `Completed` and `oracle_passed=true`;
- failed workspace oracle yields `OracleFailed`;
- protected oracle file remains unchanged;
- cleanup succeeds after completed, policy, timeout and oracle-failed outcomes.

### Adversarial

- absolute, parent, current-dir, empty and NUL paths rejected/blocked;
- symlink in workspace path rejected on Unix;
- symlink authority root rejected;
- duplicate fixture path rejected before effects;
- duplicate oracle path rejected before effects;
- non-UTF8 snapshot path fails closed on Unix;
- unsafe/empty run ID rejected before directory creation;
- no effect index is skipped or reordered;
- final snapshot contains only workspace regular files, never oracle files.
